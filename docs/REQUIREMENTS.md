## 2. 拼团阶段模型（Round Phases）

阶段按**时间窗**定义（可配），阶段决定「谁可排/撤/改」。

> **实际时间**（2026-09-17 用户确认；浮动，以管理员手动为准）：Phase 0 **手动开团**；Phase 1 约**当日 20:00**；Phase 2 约**当日 22:00**；Phase 2 起**持续 3 天**；随后**结算**；随后**下单锁定**。下表时间为示意。

| 阶段 | 时间（示例） | A 类商品（盲盒/变体，不可单买） | B 类商品（固定价单领） | 管理员 |
|---|---|---|---|---|
| **Phase 0** 开团前 | `[T0, T1)` | 不可排不可撤 | 不可排不可撤 | 录入 A/B 商品、锁定优先队列名单；可改 |
| **Phase I** | `[T1, T2)` | 不可排不可撤 | **所有人可排可撤**，自动后进补位 | 可调整 Phase 0 任意信息 |
| **Phase II** | `[T2, T3)` | **优先队列成员**可排可撤；非优先**不可排不可撤** | 所有人可排可撤，自动补位 | 除非必要不改 |
| **Phase III** | `[T3, T4)` | 所有人可排可撤 | 所有人可排可撤 | 可改商品/权限/配置并**全量重排** |
| **结算 Settling** | `[T4, T5)` | 仍接受加排/退 | 仍接受加排/退 | 录入调价/折扣/特典，试算下单表 |
| **锁定 Locked** | `>= T5` | 冻结 | 冻结 | 填写订单编号后锁定商品与下单包 |

规则：
- 阶段由 `round.phases` 配置；判定用**消息 `timestamp_ms`**（真实链路）。
- 越权请求 → **Reject**（如 Phase II 非优先排 A 类）。
- 自动后进补位：撤销释放的槽由后续认领者按排序键自动前移（既有引擎已支持）。

## 3. 结算与下单表规则

> 术语：**下单包** = 一个购买单元（对应一次下单/一份），由若干 item（商品/变体）组成；**排下单表** = 把 item 分配到各下单包的排列。

### 3.1 调价（Settlement Pricing）
- 管理员在结算前录入**所有商品及其变体**的调价。
- **标价来源**（2026-09-17 用户确认）：**无固定价目表，一律由管理员填写**。仅通行证存在计价辅助规则：单价 **¥25/个**；整盒价 = **25 × 盒内个数**（非固定 175）；多数角色含「精一/精二」两件，未注明时默认两件同购 = **¥50**，仅精一 = **¥25**；人事部简历总价取决于内含角色、风尚速递每角色 1 份、贴纸包内容不定 —— 均由管理员填写。
- WebUI 两种模式：**① 原价加减**（原价 ± Δ）；**② 直接设定调后价格**。
- **调价结果不作为最终减均、整单优惠的计算依据**（调价不影响商品类别与总价口径）；仅用于生成「调后价」列，与后续排下单表衔接。
- 计算基准：商品**标价（原价）**。

### 3.2 折扣方式 / 份数 / 作用范围
- 折扣方式：**满减**（满 m 减 d）、**全单折扣**（整单 × 率 / 减额）等，可多条。
- 每条折扣可设**份数 n**：`n = -1` 表示全部；`n ≥ 1` 表示作用于**排好序的下单表前 n 个下单包**。
- **作用范围**两种模式：
  - **A**：包含已认购特典在内的**所有商品**；
  - **B**：所有商品**但不含特典**。
- 计算时按选定模式，统一作用于相应商品集合。

### 3.3 特典档位（Gift Tiers）
- 规则：**每个下单包**金额满 `m` 即附赠对应特典；**多档可叠加**；**单包独立计算，不跨包累计**。
- 示例：某包 501 元 → 同时获得「满 0 元即送」「满 300 元」「满 500 元」共 **3 种**特典。
- 档位可**在排出下单表后**给出或确认；不同档位特典可有**各自指定价格**。

### 3.4 特典折价与减均（Gift Valuation → 减均）
- 各档特典作为**折价**：给免费特典赋价，其金额用于对**其余实购商品**做**减均**。
- 选项：**减均是否包含特典价格**——包含则特典价格进入减均范围；不包含则只对实购商品减均。
- **成团规则**（2026-09-17 定稿）：拼团一律「**成几开几**」——`成团数 = ⌊认购件数 / 每盒件数⌋`；**不足整盒一律不成团（不买）**，**唯一例外「包盒尾」**（本次月行水上无包尾）。未成团的商品**不进下单表、不计价**。
- 标价规则（A 类）：通行认证类 = `¥25 × 件数`（结城理/岳羽由加莉/埃癸斯 各 2 件 = ¥50，虎狼丸 1 件 = ¥25；整盒 7 件 = ¥175）。
- 特典认购数按「**成几开几**」（2026-09-17 确认）：`granted_X = min(认购数_X, 实际成包数 P)`；某档认购超过实际包数的部分**排失败/掉落**（不付款、不参与减均、不归属任何人）。
  - 示例：3 人排 A 档、2 人排 B 档；若只成 2 包 → `G = 2A + 2B`（第 3 位 A 排失败）；若成 3 包 → `G = 3A + 2B`（多出的 1 个 B 掉落）。
- 多档特典按**各自指定价格**分别计算。
- **未认购/掉落的特典视为溢出**，不参与价格计算。

### 3.5 排下单表模拟器 + 自动策略
- 管理员可设：商品/变体、调价、全局折扣、折扣方式与份数、A/B 范围、特典档位与价格、减均选项。
- **自动策略**两种（互斥，分别独立搜索输出各自最优）：
  - **特典最多化**：最大化命中特典档位（数量/金额）。
  - **折扣最大化**：最大化折扣总额（受「首 n 包」影响）。
- 搜索：围绕**下单包排列 × 折扣份数 × 特典档位 × 减均规则**做 **DFS/回溯**（可加剪枝/启发式）。
- 自动排列后可**手动调整**：WebUI 以**拖拽 item 到包**的交互操作。

### 3.6 整体计算流程
1. 录入基础商品/变体 + 调价；
2. 配置折扣方式与份数、A/B 范围、特典档位与价格、减均选项；
3. 模拟器按**每包独立**判断特典；
4. 按**首 n 单**规则应用折扣；
5. 按 **A/B 模式**计算折扣与减均；
6. 按「特典最多化」或「折扣最大化」分别搜索最优下单表；
7. 输出：**下单表 + 特典清单 + 折价金额 + 减均结果 + 折扣 + 总价**。

## 4. 已定稿公式（2026-09-17 用户确认）

> 权威口径；实现必须与本节的**校验式**一致。变更须同步 [DECISIONS.md](./DECISIONS.md)。

### 4.1 减均（用户修订版）
- `P` = **实际成包数**（排谷「成几开几」结果，由 ordering 引擎给出）。
- **特典认购数**（A-2）：`granted_X = min(认购数_X, P)`；排失败/掉落的特典不付款、不参与减均、不归属任何人。
- `G` = Σ(已认购特典 × 各自指定价) = `Σ_X granted_X × price_X`。
- `B` = Σ 各下单包**实付价**（折扣后金额；不含特典，特典免费）。
- `C` = **无折扣商品总价** = Σ 实购商品标价（不含特典）。
- **总优惠额** `D = C − B + G`。
- 按**各商品自身标价**加权把 `D` 分摊到各商品：`alloc_i = round2(D × price_i / C)`，并用**残差校正**保证 `Σ alloc_i = D`（精确到分）。
- 商品减均后价 `final_i = price_i − alloc_i`，**只保留 2 位小数**（四舍五入）。
- **校验式（必须成立）**：`Σ final_i + G = B`。
- 边界：`C = 0` 时 `alloc_i = 0`（无减均）。

### 4.2 搜索排序规则（原口径，通过）
- 折扣最大化：下单包按**金额降序**，使「首 n 包」金额最大；同额按 item 数降序、包 id 升序。
- 特典最多化：优先让更多包**跨过最高档阈值**；同分按总金额降序。
- 回溯剪枝：当前上界 ≤ 已知最优则剪枝。

### 4.3 调价与优惠先后（原口径，通过）
- **调价不参与**折扣/减均/特典档位计算（见 3.1）；最终展示 `调后价` 与 `结算价` 两列。

### 4.4 金额精度
- 内部以**分（cents）**为单位；展示/输出保留 **2 位小数**；所有加权分摊 = 四舍五入 + 残差校正。

### 4.5 全单折扣口径（原口径，通过）
- `整单折扣额 = Σ(折扣作用范围内金额 × 率)`，再按同一比例回摊到各包。
