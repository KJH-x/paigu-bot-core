## U1 导航与流程语义

- **Stepper 高亮 = 当前所在模块**（不是当前阶段）；**阶段进度用更弱的元素**表达（因为 hover 已有反馈，避免语义重叠）。
- 区分**开团**与**设置**：**开团只关心「轮次与商品」（round）**；其余配置（gateway/llm/display/members/白名单…）不常改、也不是流程 → 放到**单独位置**（`/settings`），**不进 Stepper**。

## U2 `round_id` vs `title`

- `round_id` = **稳定标识**（用于 `data/messages/<round_id>.jsonl`、快照目录、remote `rounds/<round_id>/current`、`RoundId`）；
- `title` = **展示名**；二者**可不同**，UI 需说明。

## U3 轮次管理（新建 / 切换 / 校验）

- 提供**新建轮次**、**切换（activate）轮次**、**校验（check）**。
- **切换与重放不绑定**：切换可能是「**继续**」「**新建**」；**重放是一项自动计算功能**，与切换互不冲突、互不绑定。
  - `activate` 模式：`continue`（**默认**；无既有状态时等价 `fresh`）/ `fresh` / `replay`。
- 轮次库布局：`config/app.json` 只留 `active_round_id`，轮次数据放 `data/rounds/<round_id>.json`。

## U4 成员具体名（CN）

- CN = **净化后的群昵称**，**绑定 QQ(user_id)**。
- 用途：① 请求匹配；② **制作结算表格**（每个人买了什么）时**自动使用 CN** 作为人名。
- **回退顺序：CN → 归一化昵称 → user_id**。
- 存储：`members.cn_overrides[{user_id, cn, aliases[]}]`（config 热载 + 乐观并发 409）。

## U5 阶段时间窗的日期提示

- 显示 **周几** + **相对日**：`前天 / 昨天 / 今天 / 明天 / 后天`（**仅这几种**）；其他情况显示 `X 天前 / X 天后`。

## U6 商品目录（编辑器与模型）

- **商品级不设置调价功能**：商品只设置**原始价格**。
- **只有变体**设置：**原价 A** + **调价 B**。
- **统一显示** `原价 A ± 调价 B = 最终价 C`，**不在模式间切换**。
- **每一格都能改**：
  - 改 **A** 或 **B** ⇒ **C 联动变更**；
  - 改 **C** ⇒ **B 联动变更**；
  - **A 不会被联动变更**。
- **`+` 红 / `-` 蓝**（字体颜色），对 **B、C 都生效**。
- `A/B/C` 仅作**说明辅助**，**不得直接用于 HTML `id`**。
- **种类（UI 用「种类」，不用 `kind`）**：`拼团` / `单领` / `整盒` / `特典`。
- `class` **自动推导**：**有变体 ⇒ A（阶段受限）**；**无变体 ⇒ B**。并区分 **拼团(A) / 单领(B) / 特典(A)**（**整盒**为独立种类）。
- **`box_size` 不必要**（拼团**逐个设置变体**；单领/整盒**不考虑内容**）→ 移除。
- **`variants[].pieces` 不必要**（数量限制按整盒/整体处理）→ 移除。
- 变体栏目需**列头与提示**；`variant_id` **不允许手填**（只读、自动生成）；允许**修改变体名**。
- **别名**：
  - **词组切分（本地、无需 LLM）**；
  - 另有 **LLM 建议按钮**，**异步请求**更佳；需**状态提示**：`等待回复 / 已填入新方案 / 是最佳`；**所有别名一起请求**。
  - **锁定按钮**：**被人工编辑过后默认自动上锁**；**上锁的不请求 LLM、也不从商品名更新**，除非手动解锁；**锁定状态下仍可自由人工编辑**。
  - **跨商品校验冲突**（失焦、切换面板时检查并在有冲突时提醒；后端 `check` 兜底）。
- **添加商品交互**：
  - 列表**末尾**一个**虚线框卡片**作为可点击入口（选择**种类**后添加）；
  - 也可通过**商品之间的缝隙**插入：hover 高亮 + 显示带底色的**圆角矩形「+」**，点击后出现虚线框卡片；**若未继续确认新增，鼠标移开后自动消失**。
- **单领**：
  - `max_quantity`（单领上限）**不应出现在拼团商品**设置中；
  - 单领**只显示 1 个 tab**，一个 tab 里可填写**多个单领**；
  - 单领也需**别名**支持与**半自动辅助填写**（填完商品名就立刻产生行；按 Tab 为**竖向优先**切换）。
  - **注意处理区分**：拼团内容的**整盒也可以单领**（见 U8）。
- **消息日志编辑器**：应出现在**排谷界面**，形式为**单独折叠面板**。

## U7 解析规则：first-match 与失败澄清

- **只报角色名、未报商品大类**且属**可拼团的拼团类 / 特典类**请求 → 默认按 **first match**（**商品目录顺序**取第一个可拼团商品；例：一般命中「通行证」而非「人事部简历」）。
- 若**全部 fail** ⇒ **排失败** ⇒ 通过 **LLM 询问**（提供商品列表，询问 first-match 是哪个），然后**保存修复后的排申请**并**作为依据**（如错别字、同音字）。
- 修复结果**写成该消息的 `ParseOverride` 事件并持久化到该轮次的事件/消息日志**，作为后续重放的依据。

## U8 整盒 / 包盒 / 包尾（分配与结算）

- **「整盒」是独立种类**，视为与单领/拼团不同；**整盒买的请求默认进入「单领」队列**，不进入拼团队列；整盒允许作为独立单领条目（例：通行证整盒 ¥175 单领）。
- `fullbox`（**包盒**）**保留为拼团策略**：一人占走某盒剩余槽。
- **包尾**请求进入**拼团**队列，并在**结算时强制成盒**。
- **「列」= 盒的序号**（一列 = 一个盒）。
- 包尾**不必置顶**：其**请求的变体集的最大列序**决定其**锁定的盒列**（= 该变体认购的最大列序 + 1）。
- 结算时：若其前有**未成盒**的拼，且这些拼**不与申报包盒时的变体集冲突**，则**自动滑入**此包尾盒。
- **用户原例**：变体 A/B/C 分别排了 **1/3/2** 个，包尾请求「**B + 包尾**」⇒ **锁定盒列 4**（A、C 空置）；结算时因 **2、3 列未成盒**、**B 被锁定顶住**，**列 2 的 C 认购人被移入列 4 的 C 槽**；而 **A 因没有未成团**故**不分配给包尾人**。
