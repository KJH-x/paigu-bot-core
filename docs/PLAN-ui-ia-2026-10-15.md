# 桌面信息架构、功能整并与可达性计划

> 状态：**持续目标执行中：G0 与 G1/G2 核心已回归，G3/G4 分区保存与草稿保护验证中；未整体验收**（2026-10-18）。最初调查基线 `5519878`，最新已推送基线 `cffb676`。
> 以下调查记录保留历史语境；实施仅用隔离占位数据，不部署、不重启常驻实例、不操作真实群。
> 验收范围：电脑端 1920×1080、100%；保留高信息密度与直角风格，不靠缩小文字或隐藏实际容量解决拥挤。

## 1. 结论与边界

问题不只是“菜单不够多”，而是 **页面职责、控制作用范围、数据上下文不一致**。

建议采用：**合并首页与管理总览；成员独立；消息操作归排谷；结算与下单归一个工作区；系统设置只承载系统配置和数据维护；全站共享一套导航与连接上下文。**

本文件是待实施方案，不表示相关页面、路由或接口已经存在；也不自动恢复旧计划的 §9 模态改造或 §11 LLM 重解析。业务规则、排序、容量、金额、事件语义不因整并而改变。涉及已发现的数据正确性问题，先过 G0 门禁，不能用布局改造掩盖。

## 2. 调查基线：哪里不直观、哪里不可达

### 2.1 页面可达不等于功能可达

已核对 7 页源码链接，并实际点击 `排谷 → 管理 → 设置 → 复盘 → 结算 → 下单 → 轮次 → 首页`。

| 当前起点 | 到设置 | 到管理总览 | 结论 |
| --- | --- | --- | --- |
| 首页 | 1 次，经正文卡片 | 1 次，经正文卡片 | 顶部导航不含这两个入口 |
| 管理总览 | 1 次 | 本页 | 与首页重复状态、入口和概览 |
| 轮次 | 1 次 | 2 次，经首页 | 导航集合与其他页不同 |
| 设置 | 本页 | 2 次，经首页 | 名称没有说明业务维护与系统维护的边界 |
| 排谷 | 2 次，经管理或首页 | 1 次 | 没有设置直达入口 |
| 结算 / 下单 | 2 次，经管理或首页 | 1 次 | 同一物理页占两个顶级步骤 |
| 复盘 | 2 次，经管理或首页 | 1 次 | 没有设置直达入口 |

7 页组成的链接图没有完全孤立节点，最长最短路径为 2 次；但排谷到成员编辑需经过 `管理 → 设置 → 成员 / CN`，用户必须先猜功能放在哪里。不能把这些情况统称为 404，也不能因此判定直观性通过。

### 2.2 已确认的问题清单

| ID | 观察与证据 | 应解决的层次 |
| --- | --- | --- |
| IA-01 | `shell.js::STEPS` 只有业务 5 步；各页另写不同 `nav-links`；“展示/排谷”“回放/复盘”混用 | 统一全站入口、名称、顺序、当前页标记 |
| IA-02 | `index.html` 与 `admin.html` 都是入口与状态概览；管理页并没有集中管理操作 | 合并重复容器，不再新增泛化“管理中心” |
| IA-03 | 成员 CN、消息编辑、系统接入和快照导入混在设置；首页、排谷、设置都挂消息编辑器 | 按任务整并，而非按现有配置对象分组 |
| IA-04 | `settings.js` 将“保存成员 CN”绑定到全量 `save()`，后者调用 `collectConfig()` 收集其他设置 | 保存按钮名称必须等于实际保存范围 |
| IA-05 | 接入复选框待保存，但旁边“切换开关”立即生效；重新载入与从磁盘重载并列 | 统一提交模型，隔离维护动作 |
| IA-06 | `common.js`、`shell.js`、各页读取 API 地址的方法不同；普通链接不保留显式 API 参数 | 同一导航必须保留同一实例、轮次及数据来源 |
| IA-07 | 在结算页点击“4 下单”，URL 变成 `#order`，仍高亮“3 结算” | 把工作区导航、页内位置、阶段进度分开 |
| IA-08 | 设置的 DOM 顺序为接入→展示→LLM，视觉却把 LLM 放在右上；Tab 从远程地址跳回右上模型开关 | 视觉、阅读、键盘顺序一致；不要靠 CSS 换序伪造层级 |
| IA-09 | 设置、轮次、结算页没有语义标题；首页无 main 地标；多处只有泛化“保存/删除/切分” | 标题、表格、按钮名称与焦点语义补齐 |
| IA-10 | 轮次 `category`、测试群 `test_group_id`、实验合并、整盒关联 `box_item_id` 没有对应 UI 控制 | 已有能力必须明确归属：常用可见、高级可达，不能只靠手改文件 |
| IA-11 | `round.js::normItem/serializeItem` 未携带 `box_item_id`；配置有该能力但目录保存链不完整 | 往返保真门禁：先验证，不能在搬迁表单时继续丢字段 |
| IA-12 | 接收器为 0 时，仍有绿色 NapCat 状态；与 API 正常、服务监听正常混在一起 | 分别表达 API、接收器、数据新鲜度与只读状态 |

IA-11 是源码确认的字段遗漏风险，本轮未提交保存请求验证其最终落库影响，不能声称已复现生产数据损坏。

本轮正向验证：成员锚点实际到达章节，随后 Tab 能进入成员操作；快照锚点可达；没有把短暂滚动动画中的焦点位置当成永久遮挡故障。复盘/结算在加载期间保留导航。此前已确认的吸顶遮挡、模态焦点问题仍需修复。

### 2.3 仍须先处理的数据门禁

此前隔离审查的三个 P1 尚未修复：

1. 人工确认用消息流 seq 提交，可能覆盖另一条持久化消息。
2. 清洗后昵称逐字编辑与 CN 跟随状态错误，保存后丢失完整输入。
3. 最终锁定校验要求无人认领商品也有订单价格，阻断锁定。

补充门禁：有整盒关联的目录，在无关字段修改后保存，关联不得消失。布局工作不能绕过这些用例；尚未覆盖到的锁定态拖动也不能标记通过。

## 3. 目标信息架构

```text
全站固定导航（同一顺序、全部可见，不放进“更多”）
├─ 总览                  index.html：状态、待办、任务入口
├─ 轮次与商品            round.html：轮次库、轮次设置、商品、阶段
├─ 排谷                  display.html：排位、消息处理、成员认领
├─ 结算与下单            settlement.html：规则 / 排包与订单 / 结果与策略
├─ 复盘                  replay.html：当前轮次逐步核对
├─ 成员                  members.html：称呼、别名、缓存来源（拟新增）
└─ 系统设置              settings.html：接入 / 消息理解 / 展示默认 / 数据维护

管理总览 admin.html、/admin → 总览兼容入口（拟调整，保留上下文）
```

- 5 个业务入口与“成员 / 系统设置”用轻量分隔区分，不引入第三个泛化管理页。
- 不是机械减少页面数量：删除一个重复工作区，释放一个任务入口给成员维护；核心是每个功能只有一个编辑真源。
- 每页可一次点击到其余 6 个工作区；页内子项不超过一级。跨区任务提供指向具体子项/记录的上下文链接。
- 品牌链接统一回总览；当前工作区标题单独显示，不再用“轮次复盘”等页面名作为回首页链接的名称。
- 业务阶段只作弱状态提示，不控制可达性；未配置、断线、锁定时仍能导航，写操作才按状态禁用并说明原因。
- `/` 现实际指向排谷，不是总览。本计划暂保留该默认入口，不擅自改变启动行为。
- `members.html` 是拟新增页面；实现时同步静态路由、页面注册和测试，不提前宣称 `/members` 已支持。

## 5. 各工作区的信息与控制安排

### 5.1 共用页壳

- 第一行：品牌、固定 7 入口、主题；第二行：当前工作区标题、轮次、正常/测试标识、数据来源/时间、当前任务操作。
- 一级导航与页内导航不重复；不再并列三套“首页/管理/步骤”链接。
- 页壳尽量控制在两行内；错误贴近触发控制，不靠无限增高全局横幅挤压表格。
- 页内选中项由 URL/hash 与真实可见面板一致决定；浏览器返回/前进恢复选中项，不仅滚动一下。
- 当前轮次切换只通过显式轮次激活操作；查看链接、成员筛选、URL 参数不能静默激活或改群。

### 5.2 总览与轮次

- 总览保留密集状态与异常清单；每条异常有明确“去配置接入/查看待确认/核对订单”入口，不重复整张编辑表。
- 轮次库与当前轮编辑分清：明确“正在编辑谁”“谁已激活”。创建后不假装已激活；激活与重算保留不同意图。
- 新建/激活等短事务可用模态；目录和阶段长表优先页内工作区。旧计划 §9 的“全部模态化”改为待确认设计决定，不直接补做。
- 商品名按约 10 个中文字可视宽度设计，长值仍可编辑/查看全文；别名获得余下空间；日期约 20–22ch 并实测日历按钮可见。

### 5.3 排谷与消息

- 排位和消息保留双区同屏；消息增加“待确认/拒绝/全部”等定位，不把低频维护表再塞进所有页面。
- 点击待确认/问题消息进入同一个记录详情，默认展示原文、具体原因、候选及当前解析；编辑前后差异可核对。
- 消息操作使用 record_id、记录版本及轮次守卫；不得用显示序号当写入身份。
- 从成员/复盘进入消息详情时保留来源与返回位置；只读复盘点“去处理”才进入可写排谷区。
- 原位修订按 2026-10-16 已确认口径改为 [完整动作 override 专项计划](./PLAN-message-reprocess-2026-10-15.md)：原自动结果保留，附管理员解释，实际使用完整替换动作；保存/执行不重跑 LLM、不二次确认。修正当时意思、保留原时间和后续撤排等操作。
- 已接受低负担编辑：当前动作默认带入，动作句直接点改；复杂说明可主动用 LLM 代填同一草稿，仍可手改。只有代填请求模型，保存不再请求；无需 JSON 编辑器或全字段大表单。
- 手工合并是补充性修订：主条动作替换、补充条人工拒绝，一笔原子保存/重算，可单步撤回；不是多笔订单联合 LLM 解析。优先名单修改只重验权限与逻辑重算。
- 旧消息修订须通过独立投影版本通知、按 record_id 原位更新，不能依赖“只拉 seq 更大的新消息”。原因码直接链接相应设置，返回后保留原消息与草稿；设置变更不是对单条越权放行。

### 5.4 成员

- 将“群名片 → 自动清洗 → 最终 CN”表达成来源与结果，不让两个相似输入框争夺同一保存值。
- 推荐最终 CN 只有一个编辑点，清洗结果作为只读预览；提供“恢复自动”。这是对旧两列可编辑方案的建议调整，实施前确认；若保留双编辑点，必须明示跟随状态并测试状态机。
- 表格内只放名称/别名等业务信息；缓存路径、定时拉取、完整 ID 进详情/高级区，不能删除必需诊断能力。
- 批量 LLM 建议先展示改前/改后，默认不覆盖人工 CN，明确发送字段与目的服务；确认应用到草稿，再保存。
- 现后端是单成员缓存，不虚构多群缓存能力：显示“缓存所属群”与“当前轮群”差异，不能随导航自动覆盖缓存或触发拉取。

### 5.5 结算与下单

- 一个顶级工作区，页内“规则 / 排包与订单 / 结果与策略”；原 `#order` 仍能直达正确子项。
- 规则显式保存；订单草稿沿用自动保存，但必须区分未保存/保存中/已保存/失败/冲突。
- 锁定前将缺订单号、重复订单号、排包差额、价格问题列成可点击清单，点后定位具体行；不能只给全局一句失败。
- 拖动保留，同时加“移动到包…”点击/键盘替代；两条路径用同一搬移逻辑。锁后所有写入、拖动与替代操作共同禁用。

### 5.6 系统设置与数据维护

- 四个稳定子项：接入 / 消息理解 / 展示默认 / 数据维护；一次显示一个任务组，减少两列跨区跳转。
- 配置采用分区显式保存。即时命令与配置草稿分开，不能同一布尔值既有待保存复选框又有“立即取反”按钮。
- 真实群回复与管理员动作需明确风险、当前值和适用范围；本计划不启用任何发送或扩大允许动作。
- “重新读取服务器值”与“从磁盘重载服务配置”名称、位置与影响分开；后者移维护区并要求先处理未保存草稿。
- 备份导出说明是本机文件路径，不冒充浏览器下载；当前完整快照包含敏感数据，不提供“分享”措辞。公开投影/远程发布不在本计划内。
- 导入先预检并展示目标轮次、内容和影响，再单独应用；不让一个隐蔽 apply 复选框决定是否覆写消息并重算。

## 6. 保存、上下文与边界契约

1. **单一连接解析**：统一显式 URL、用户明确选择和部署默认值的优先级；同源部署不默默退回另一端口。页壳状态与正文请求必须来自同一实例。
2. **路由上下文**：api 跨页保持；source/remote/round 按目的页白名单处理，不把远程快照地址当可写 API，不盲目复制所有查询参数。
3. **一次保存一个作用域**：成员按钮只改成员称呼/别名；规则按钮只改结算规则。沿用现有接口时，在最新完整配置上白名单合并并校验 revision，不用局部对象覆盖全局。
4. **保留未知/非本区字段**：目录序列化不得丢整盒关联；保存高级功能未显示的配置也必须保真。失败时保留输入，409 展示差异而不是要求用户盲目重输。
5. **离开保护**：有未提交草稿时，导航、激活轮次、切换实例、导入应用均先让用户保存/放弃/取消；浏览器关闭给标准提醒。原地 tab 切换不丢草稿。
6. **轮次/来源守卫**：请求发起后若 active_round_id、实例或来源改变，旧响应不覆盖新界面；写入的预期轮次不符就拒绝，不能按新激活轮次重新解释旧记录。
7. **读写分层**：当前轮复盘、导入回放和远程快照明确只读；隐藏按钮不等于服务端鉴权。未来公开展示须使用独立公共投影，不能把本地管理页直接发布。
8. **不改变契约的假象**：UI 串联不能假装后端支持不存在的功能。若记录版本/轮次守卫需扩展 DTO，先更新 INTERFACES 并单独评审，不改冻结 bus 来迁就布局。

## 7. 直观性与可访问性规则

- 一页一个可识别主标题、main 地标；章节用真实标题，多个导航有不同名称；表格保留表头关联。
- 所有输入都有业务标签。重复按钮带记录上下文；图标不能成为唯一名称，锁定/包尾/变化不能只靠颜色。
- 焦点样式清楚；吸顶层不能遮住当前焦点、锚点标题或必需按钮。DOM/阅读/Tab 顺序与视觉顺序一致，不用正 tabindex 补救乱序。
- 折叠控制的名称与 aria-expanded 同步；收起/展开不丢选中项、过滤条件或当前复盘步骤。
- 模态具备名称、dialog 语义、初始焦点、Tab 约束、Escape 与关闭后焦点恢复；需确认未保存时先处理草稿，不用 Escape 静默丢数据。
- 长表用明确滚动区域；不以外层+嵌套两套竖向滚动隐藏操作。商品超宽仍只在内容区横滚，绝不省略真实空位/容量。
- 关系图先按商品聚焦与分组，再提供定位/适配视区；表格/列视图仍为完整核对入口，不以缩小字体强塞全图。

以上参考 W3C/WAI 的一致导航、焦点可见、模态与拖动替代说明，作为本项目验收依据，不宣称已完成 WCAG 全面认证。来源见 §12。

## 12. 参考与验收依据

- [WAI：一致导航](https://www.w3.org/WAI/WCAG22/Understanding/consistent-navigation.html)：重复导航保持可预测的相对顺序。本计划选择固定可见入口，是项目设计取舍，不是该标准强制要求恰好 7 个菜单。
