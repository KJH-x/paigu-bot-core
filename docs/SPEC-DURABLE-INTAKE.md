# 本地持久入站与可观测恢复（2026-10-22）

范围为 T-23。只改本机接收/处理交接，不改排位、容量、权限、人工修订或业务排序；未部署。不引入模型重解析按钮，也不把原始消息发布到远程。

## 1. 问题与边界

旧网络读任务在等待业务 writer 后再 spawn。writer 跨模型等待时，第二条消息会把同连接的 echo 卡在后面；简单换成有界 send，队列满时仍然卡住网络回包。已用真实本地 WS＋阻塞 sink 复现失败，不能只用空队列测试证明修好。

现在网络入口先处理 echo；有效 OneBot 帧在独立本地待处理区落盘，再通知一个业务 worker。内存通知通道容量为 1，仅合并“有工作”的唤醒，不装消息、不代表丢弃消息。worker 按接收提交序号取当前轮文件，每次处理一帧，帧内批次仍按原合同排序。

```text
网络读取 → echo直接回送
        → 本地原子入站文件 → 单个worker → 原始事件同步 → Pipeline → 结果同步 → 确认删除入站副本
                              ↑ 容量1唤醒；满只合并唤醒，消息仍在文件中
```

- **有界的是等待帧的内存交接及 worker 数，不是全部进程内存/磁盘**。消息投影、已处理身份索引和历史仍随数据增长；磁盘待处理区无自动删除/丢尾/有限容量承诺，需监控本机空间。
- 网络帧/消息上限 1 MiB，本地封装上限 4 MiB（含原始完整 JSON 与归一化事件）。超限、磁盘满或写失败会停止该连接并显示故障，不继续当成保存成功。
- 不等待业务 writer 不等于磁盘永远即时响应：本地文件系统同步本身会花时间。未落盘/超限帧没有接收成功承诺；OneBot 无应用级持久接收确认，不能声称上游断线必然重传或绝对零丢失。
- 出站动作的原有队列不在本项有界证明内。未增加 send 权限；表情仍须显式配置，移到处理成功后串行发送，失败不重新执行业务。

## 2. 私有存储与身份

实际位置是消息日志事件目录（可由测试环境变量隔离）下 `_ingress/<round_id>/<20位序号>.json`，生产默认位于 gitignored `data/events/`。版本 1，保存独立 UUID、接收序号、轮次/群/类别绑定、配置版本、完整原始 JSON、规范事件、路由拒绝原因、表情配置及原始事件检查点。文件不是公共分享格式，也不并入成员展示快照。

先原子写临时文件并同步，再安装确定名称；只在处理及消息/事件目标文件同步完成后删除入站副本。崩溃遗留 `.tmp` 不是已接受消息，不自动当成新工作。未知文件/损坏头文件/版本或身份不符会停止恢复，不跳到后续文件，也不自动清空。

`IncomingEvent` 与 `MessageRecord` 可带 `ingress:{id,part}`，旧记录缺省 None，序列化省略 None。不改变已有自动结果的输入指纹，不给旧历史伪造接收身份。测试批次和代理分段派生稳定 part；同一接收副本重试，与上游真正再次发来相同 message_id 是两件事：前者不重复执行/不新增处理行，后者仍保留独立 Duplicate 行。

原始完整 JSON 先保存至原事件日志，包括测试批次数组外层及未知扩展字段；持久检查点后不再重复追加。若进程恰在原始写入与检查点之间退出，原始审计可能重复一条，**不承诺原始审计物理恰好一次**；执行身份独立，不因此新增动作。未完成理解尚未保存时，恢复可能再次请求模型；已经完整保存的理解结果绝不重新问模型。

## 3. 轮次与恢复

- worker 只处理当前激活轮且群号/类别仍匹配的文件；在真正业务 writer 内再次核对。切轮不把旧文件改归新轮，旧轮积压暂停，重新激活后继续。
- 除身份绑定和接收时的路由结果外，未开始理解的帧使用处理时当前配置（模型、合并、权限等）；接收配置版本用于审计，不是假称已保存当时整份配置。已经保存的理解仍冻结，配置变化只走现有确定性重算。
- 同轮修改群/类别、fresh 激活、删除含积压的轮次、HTTP快照导出/应用及测试 reset，先在短接收栅栏内检查积压，返回 409 `pending_ingress`，不覆盖/清空。普通 continue/replay 切轮和业务配置重算不被一概禁用。
- HTTP快照导出是已完成消息的切面，不含入站待处理区；开始时若已有积压则拒绝。栅栏检查之后新接收的消息仍属于待处理，不虚称已包含在导出中。管理员控制`/导出`保留其原有“本条控制记录保存前”的已完成动作切面，内部复用严格来源/封包，而不等待自身帧被确认；它不删除/确认待处理帧，不运行尚未保存的动作。原始审计可能含未执行文本，导入不重处理原始帧或恢复队列；坏行/任何Pending消息仍拒绝导出或应用，没有公开跳过idle参数。完整本机灾备还须私下保留整个运行时目录，不可上传公开仓库。
- 业务失败保留头文件、暂停 worker，不每隔一段时间重问模型。worker 异常退出也显示暂停；新消息不能悄悄重启失败工作。明确重试才恢复 worker/容量1唤醒。
- 进程重新启动会扫描并尝试恢复待处理文件；暂停标志本身不持久化，不将其误称永久禁用。Gateway 销毁中止 worker，没有永久 Arc 环；文件保留供下次启动。
- 正常启动仍由现行持久重放恢复状态。加载接收身份不偷偷把 `fresh`/测试 reset 改成 replay；同帧恢复或失败脏状态才从日志校正。待理解 Pending 不是已处理的重复消息。
- 同组代表已写成功而成员收据未写时，只从完全匹配输入、合法代表/版本的已存理解恢复成员；没有保存结果时复用 Pending 的稳定记录身份，不能再追加同身份行。损坏消息/事件历史不容错跳过后重新理解入站消息。

这覆盖普通处理失败、任务取消/进程重启、部分子项提交与确认失败，不是物理断电认证、磁盘损坏修复、通用 exactly-once 外部副作用或无限存储方案。管理员阶段命令、表情及外部服务不因此获得跨系统事务保证。

## 4. 可达的状态与恢复控制

`GET /api/gateway/status`，以及 workflow.gateway/board.status 内增加：

```json
{"intake":{"pending":2,"pending_by_round":{"test_round":2},"wake_capacity":1,"paused":true,"last_error":"入站待处理记录未完成；保留原文件等待恢复","worker_running":true}}
```

`pending` 包括当前正在处理且未确认的帧，不是解包后的动作数；inactive 轮次分别列数。状态为本地可信管理信息，不能原样公开。

全站顶部积压/暂停链接直达“系统设置 → 接入”，保留当前 API 连接。该页显示本轮/总待处理、故障与处理器状态；正常时禁用重试。键盘可操作，失败保留其他分区草稿。

`POST /api/gateway/intake/retry` 必需 `round_id`、`config_revision`，拒绝未知字段；在共同 writer 内核对当前上下文，过期或跨轮返回 409 `intake_context_changed`，不切轮、不改配置、不主动向群发消息。成功只是请求继续，不表示所有积压已完成；仍看状态。按钮明确说明未保存结果可能调用模型，不暗中重解析已有结果。

## 5. 隔离证据

- `gateway/ws_server/intake_tests`：256 条积压时同连接只读 echo 500ms 内可达；释放后 FIFO 全到；任务终止后无实时接收器恢复；切轮/绑定变更暂停；故障单次尝试且手动重试；worker panic 后新消息不自动重启；原始扩展元数据与原始检查点保留。
- `intake_storage_tests`：容量1唤醒/32条磁盘 FIFO；重新打开继续；坏头不跳过；保存/确认失败不减计数；未知文件保留且阻止破坏性操作。
- `pipeline/ingress_tests`：保存后重启不重复理解/动作；真正上游重复仍独立行；模型后提交失败不被瞬态 seen 吃成 Duplicate；已部分完成的 NC 批次/代理段；同组部分完成与 Pending；绑定不符零副作用；导出/应用/fresh/删除/身份变更守卫；坏历史不重解释。
- 桌面复用现有 1920×1080、100% 全套，设置页占位暂停状态检查明暗主题、无横向溢出、恢复入口、键盘提交观察到的轮次/版本及真实跨轮 409；这是 UI 故障夹具，真正持久故障由 Rust 替身验证，不破坏 UI 服务日志。
