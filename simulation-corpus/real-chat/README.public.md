## 一、md 数据表是否足够？（反馈）

**结论：作为「名称 / 价格目录」够用；作为「排谷商品目录」不够，需补充。**

md 提供的（月行水上）：14 个本期新品 + 价格、活动信息（满赠满¥259赠特典卡组一套 / 立减12%）、7 个「多款」商品的子变体清单。

md **缺失**、但排谷必需：① 套组按角色拆分（人事部简历SP / 风尚速递SP 实际按角色认领）；② 满赠特典「特典卡组-校园凭证」没有角色变体与「整套」；③ 认购计数/盒规/单抽·整盒数量；④ 拼团 vs 单领、口语别名（通行证/特典/一套…）；⑤ 变体顺序。

→ 本次用 md 定商品名/价格，用真实聊天 + xlsx 补齐角色变体与别名。

## 二、政策（Policy）

| 规则 | 说明 |
|---|---|
| 优先时段 | `[2026-09-07 20:00, 22:00)`（**end 独占**），**仅预存(购物金)用户**可排；其余请求**拒绝** |
| 全量时段 | `2026-09-07 22:00` 起，所有人可排 |
| 优先用户 | `用户A, 用户B, 用户C, 用户D`（预存/购物金） |
| 昵称归一 | 去掉玩笑/备注括号：`用户B（备注）→ 用户B`、`用户C（备注）→ 用户C`、`用户E（备注）→ 用户E`、`用户J（备注）→ 用户J`；`A（代B）` 保留并统一半角括号 |

配置写在 `月行水上/round_config.json` 的 `priority_users` 与 `priority_window{start_ms,end_ms}`。

## 五、引擎/解析器增强

- `ItemVariant.aliases`（`一套`→`整套`）；`ItemVariant` 变体名可含别名。
- 规则解析器**上下文绑定**：变体优先绑定紧邻商品名（`结城理通行证` / `通行证结城理` / `特典 虎狼丸`），否则取最近商品。
- 相邻「商品名 + 变体」合并：`特典卡组-校园凭证 虎狼丸` 只认领变体，不重复认领基项。
- 规则解析结果带 `resolved_item_id/variant_id/round_id` 直传校验层，避免二次全局重解析歧义。
- **优先时段政策**：`priority_window` 内非 `priority_users` 的请求 → Rejected；预存用户全程 `priority_level 10`。
- 昵称归一：去括号备注（保留 `(代…)`）。
