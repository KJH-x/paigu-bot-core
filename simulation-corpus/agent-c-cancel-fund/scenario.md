## 引擎假设（用于手推）

1. 加购累加；`改X为N` 直接设值（N=0 删除）；`撤XN` 减 N，减到 0 删除。
2. 裸 `撤` = 撤销该用户本团所有生效订单（整条撤）。
3. 排序键 = **购物金优先 > 生效时间 > 消息序号**；「生效时间」取该用户在该商品上最近一次变更消息的 `timestamp_ms`。
4. `包盒` = 认领一整盒（split 商品加 `box_size` 个）；`包尾` = 补齐当前盒尾，加 `box_size - (当前总数量 mod box_size)` 个。
5. `X改成单领` 仅改领取策略，不改数量。
6. 被撤用户移出队列，其后所有人自动前移（连锁）。

## 存疑点

1. **裸 `撤` 的语义**：本稿按「撤销该用户本团全部订单」处理；若实现为「仅撤最近一条」或「撤当前正在讨论的商品」，最终结果会不同（尤其 c43–c47）。
2. **生效时间取值**：`改X为N`、`撤XN`、`/修正`、`包尾/包盒` 之后，排序用的「生效时间」应取原始加购时间还是最近变更时间？本稿取最近变更时间；若取原始时间，丙/庚、甲/丁 的次序可能变化。
3. **`包尾`/`包盒` 精确语义**：`包尾` 补几个（按当前盒余量还是按整盒）、`包盒` 是否独占新盒且不可再 `改单`，均无定论；本稿给出的是自洽假设。
4. **`X改成单领`**（c30 乙）：乙当时并无立牌订单，属「无订单改策略」，应报错还是静默忽略未定。
5. **管理员 `/加优先` 与购物金的叠加**：c11 给本就带购物金的丙加优先、c50 给非购物金乙加优先。`/加优先` 是否等价于购物金优先级、还是独立更高一档，会改变 c50 之后的燐音吧唧次序（本稿未把 c50 视为改变排序，仅记录）。
6. **`/锁位`**（c26）：锁位后是否拒绝后续 `撤`/`改单`（c28 甲撤、c29 丙改）未定；本稿假设锁位仅冻结盒结构、不阻止个人改撤。
7. **并发时间戳**：c8/c9 同为 605000ms，排序需依赖 `source_sequence` 兜底（二者分属不同商品，本稿无冲突）。
8. **gift 商品（特典色纸）** 是否参与购物金优先排序、是否占盒，未定；本稿按普通队列处理。
